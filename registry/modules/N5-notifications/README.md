# N5 «Сповіщення»

Модуль erp-ui (SPEC §14, §17; ADR-0013, ADR-0014, ADR-0020, ADR-0025, ADR-0046): сторінки центру сповіщень і налаштувань, web push на пристрої, лічильник у назві вкладки.

- **Сповіщення** — сторінка `paths.inbox` зі спільною частиною кіта `erp/notification-inbox`: усі й непрочитані, позначки, «Прочитати все», «Показати ще». Без мережі показує «Немає з'єднання», збій «Показати ще» лишає показане й дає «Спробувати ще».
- **Налаштування сповіщень** — сторінка `paths.settings` з `erp/notification-settings-form`: події й канали, тихі години, блок «Push на цьому пристрої».
- **Push на цьому пристрої** — увімкнути, вимкнути, надіслати перевірку. Браузер без push чи із забороною каже, що робити. Дозвіл просимо лише після натискання. Бекенд без адрес push блоку не має.
- **Лічильник у вкладці** — «(3) Рахунки», як на дзвінику.

Дзвіник, лічильник у вкладці й реакцію на push дає `InboxBell` в оболонці, вони працюють і без модуля. Модуль додає сторінки, пункти навігації, фоновий файл, фікстури й тип розширення.

## Встановлення

```sh
node scripts/erp-ui-kit.mjs update <версія кіта> --add modules/N5-notifications
```

Файли модуля стають у `src/modules/N5-notifications/`, спільні компоненти кіта, яких бракує, — на свої місця (`src/components`, `src/lib`, `src/hooks`), фоновий файл — у `public/erp-ui-push-sw.js`. Файли модуля в проекті не правимо: зміни під клієнта — у файлі розширення.

## Підключення

```ts
// src/modules.ts
import { createNotificationsModule } from "@/modules/N5-notifications"
import { notificationsExtension } from "@/extensions/N5-notifications"

export const notificationsModule = createNotificationsModule({ extension: notificationsExtension })
```

```tsx
// Топбар оболонки: лічильник у вкладці ввімкнено, `tabCounter={false}` вимикає.
<InboxBell onNavigate={navigate} onShowAll={() => navigate(notificationsModule.paths.inbox)} />
```

- Маршрути — `notificationsModule.routes` (React Router) під `Suspense` і межею помилок застосунку; сторінки — лінивими чанками. Адреса `basePath` веде на сповіщення.
- Навігація — `notificationsModule.nav`. Прав немає: людина бачить лише свої сповіщення.
- `notificationsModule.preload(pathname)` — наперед завантажити чанк сторінки.
- Застосунок має стояти в корені домену, HTTPS обов'язковий (на `localhost` браузер дозволяє й без нього). Фоновий файл реєструється з адреси `/erp-ui-push-sw.js` в області `/erp-ui-push/`, тож не заважає MSW і PWA.
- Рядки модуля — свій простір імен `N5-notifications`. Рядки блоку push — у кіті (`push.*`).

## Де працює push

Chrome, Edge, Firefox і Safari на комп'ютері, браузери на Android. На iPhone і iPad push працює лише в застосунку, доданому на головний екран, а для цього потрібна PWA. Її ще немає в кіті, тому блок там пояснює, що потрібно, а кнопки не показує (вікторина N5).

## Розширення під клієнта

Файл проекту `src/extensions/N5-notifications.ts` (тип `NotificationsExtension`):

- `inbox.perPage` — сповіщень на сторінку, типово 20.
- `strings` — перевизначення рядків модуля за ключами `i18n/uk.json` і `i18n/en.json`.

Події й канали дає сервер, тож колонок, фільтрів і полів тут немає.

## Контракт API

Центр сповіщень і налаштування — `lib/notifications`, `lib/notification-settings` (ADR-0013, ADR-0014). Новий лише push, `lib/web-push`, під `/api/v1`, для людини, що ввійшла:

- `GET /me/push/public-key` → `{ publicKey }`: відкритий ключ VAPID (base64url). Закритий ключ лише на сервері. Ключ можна замінити без нової збірки: кіт перепідпишеться під час наступного запуску.
- `POST /me/push/subscriptions` `{ endpoint, expirationTime, keys: { p256dh, auth } }` → 204. Запис один на `endpoint`, повтор його оновлює. Кіт надсилає його після ввімкнення й під час кожного запуску застосунку. Мова push — з `Accept-Language`.
- `POST /me/push/subscriptions/remove` `{ endpoint }` → 204, зокрема для невідомої адреси. Адреса в тілі запиту: це секрет пристрою, йому не місце в журналах.
- `POST /me/push/test` `{ endpoint }` → 204: перевірочний push на цей пристрій, в інбокс не йде, зі своїм `id` щоразу, інакше браузер тихо замінить попередній. Невідома адреса — 404.
- Під «Увійти як…» запис у `/me/push/*` — 403 `impersonation_forbidden`.
- Немає адрес push: `GET /me/push/public-key` → 404, блоку в налаштуваннях тоді немає.

Що робить сервер:

- Надсилає JSON `{ id, title, body?, link?, icon? }` шифром `aes128gcm` (RFC 8291), до 4 КБ, мовою підписки. `id` — сповіщення центру: той самий `id` не показується двічі, клік у відкритому застосунку позначає його прочитаним. `link` — шлях застосунку, як в інбоксі; чужий домен кіт не відкриває.
- Текст push видно на заблокованому екрані: що туди писати, вирішує проект для кожної події.
- Сам дотримує вибору каналів і тихих годин.
- Ставить термін життя за подією. 404 і 410 служби браузера — видалити підписку: так само відпадає підписка після явного виходу, бо кіт скасовує її в браузері. 429 і 5xx — повтор із `Retry-After`.

### Чия підписка

Один пристрій має підписку лише однієї людини.

- **Людина натиснула «Вийти»:** кіт скасовує підписку в браузері й закриває показані сповіщення.
- **Автовихід за бездіяльністю чи сесія закінчилась:** підписка лишається, інакше push зникав би після кожного простою, а саме тоді він і потрібен. Сервер сам вирішує, чи надсилати текст такій людині, див. нижче.
- **На пристрій увійшла інша людина:** її вхід скасовує чужу підписку.
- **«Увійти як…»:** підписку адміністратора кіт не чіпає, блок показує пояснення замість кнопок.
- **Браузер зняв підписку сам,** а людина її не вимикала: кіт підпише пристрій знову під час запуску.

### Що перевіряє сервер

`endpoint` приходить від браузера, а сервер іде за ним сам. Без цих перевірок адреса стає запитом сервера куди завгодно (SSRF).

- **Адреса.** Лише `https`, порт 443, без логіна в адресі, до 2048 символів, хост зі списку служб: `fcm.googleapis.com`, `*.push.services.mozilla.com`, `*.push.apple.com`, `web.push.apple.com`, `*.notify.windows.com`. IP перевіряти під час з'єднання, редиректів не виконувати, тайм-аут і межа розміру відповіді обов'язкові. Клієнту лише 204, 404 чи узагальнений 502, без відповіді служби.
- **Власник запису.** `remove` і `test` лише для запису цієї людини. `save` чужого `endpoint` переносить запис новій людині: пристрій один.
- **Ліміти.** До 10 підписок на людину, обмеження частоти на `subscriptions` і `test`. Ключі `p256dh` і `auth` перевіряти за довжиною й форматом.
- **Журнали.** `endpoint` і ключі не записувати: хто їх знає, може надсилати на пристрій push.
- **Перед кожним надсиланням:** обліковий запис активний, людина ще має право бачити подію.
- **Коли видаляти запис:** «вийти всюди», зміна пароля, блокування, вилучення з компанії, 404 чи 410 служби. Кіт цього не знає: на його боці лише явний вихід.
- **VAPID.** `sub`, `aud`, `exp` не довше 24 годин; закритий ключ у сховищі секретів; своя пара на кожне середовище. Після заміни ключа 401 і 403 служби не видаляють запис одразу: браузер перепідпишеться під час запуску, тож видаляти через кілька днів.
- **Текст** видно на заблокованому екрані: для чутливих подій нейтральний текст, подробиці всередині застосунку.
- **Роздача `public/erp-ui-push-sw.js`:** `Content-Type: text/javascript`, `Cache-Control: no-cache`, `X-Content-Type-Options: nosniff`, без підміни на `index.html`. У CSP `worker-src 'self'`.

## Моки

```ts
import { createNotificationsMocks } from "@/modules/N5-notifications/mocks"

const notifications = createNotificationsMocks({ users: ["u-1"] })
setupWorker(...createPlatformHandlers({ inboxSeeds: notifications.seeds }))
```

Адреси віддають моки платформи (`lib/mock-inbox`, `lib/mock-notifications`, `lib/mock-push`), модуль їх не дублює: він дає лише початкові сповіщення. Сценарії (`success`, `error`, `empty`, `slow`, `conflict`, `forbidden`, `offline`) — ресурс `notifications`, у панелі розробника чи `lib/mock-scenarios`. `empty` дає порожній список і нуль непрочитаних, `conflict` — 409 на запис. Події налаштувань дає проект, тож там `empty` працює як `success`. Служби браузера в моках немає: перевірку показує сама сторінка.
