# erp-ui: Кіт у проекті

Довідка скіла `erp-ui` (встановлення й оновлення командою кіта, файли кіта, нова залежність). Відкривай, коли задача зачіпає тему; правила ядра (`../SKILL.md`) діють і тут.

- **Залежності проекту** команда кіта не змінює: ставить лише відсутні з діапазоном кіта, версію поза діапазоном кіта лише називає.
- **Встановлення й оновлення кіта** — лише командою кіта в проекті (ADR-0029): `node scripts/erp-ui-kit.mjs update <версія> --add <елемент>` (новий елемент), `update <версія> --dry-run` (що зміниться), `update <версія>` (оновити всі встановлені), `check` (файли кіта й `kit-files.json` не правлені, сироти названо; у `pnpm lint`), `update <версія> --prune` (видалити незмінені файли-сироти, яких у новій версії немає). Наприкінці звіту `update` — розділи «Що зробити в проекті» між версіями: виконай їх. `shadcn add` напряму не запускай: елемент не потрапить у `kit-files.json`, а модуль напряму з GitHub — це тисячі запитів без повтору. Файли `scripts/erp-ui-kit*.mjs`, `scripts/erp-ui-check-tokens.mjs`, `e2e/erp-ui.ts` і `kit-files.json` руками не правиш.
- **Файли кіта не правиш** — ні модулів, ні спільних шарів (`ui`, `erp`, `templates`, `lib`, `hooks`; ADR-0076). Модуль — лише файл розширення (правило вище). Бракує можливості компонента — пропозиція PR у реєстр; чекати не можна — свій компонент під іншою назвою в коді проекту, файл кіта лишається як є. Позначки `local override` більше немає: `update` зупиняється на файлі з нею.

## Нова залежність
Додавай лише після перевірки чотирьох бар'єрів:
1. Ліцензія: MIT, Apache-2.0, BSD, ISC, Zlib; з подвійної «MIT або GPL» — MIT (без копілефту, SSPL, ELv2, Hippocratic, EPL, BSL).
2. Реліз за останні ~6 місяців і React 19 у peer-залежностях.
3. Працює з Vite і токенами Tailwind v4 без другого рантайму стилів.
4. Походження вендора відповідає політиці.

Звір із червоним списком у SPEC §5. Платні бібліотеки — лише за погодженням під конкретного клієнта.
