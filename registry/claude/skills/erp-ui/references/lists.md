# erp-ui: Списки й таблиці

Довідка скіла `erp-ui` (таблиця, вкладки й фільтри над списком, масові дії, редагування в комірці, сторінка списку). Відкривай, коли задача зачіпає тему; правила ядра (`../SKILL.md`) діють і тут.

- **Списки й таблиці** (ADR-0016) — лише `DataTable` з `erp/data-table`: великий список — `list={useWindowedList(resource, { sort, filter })}` (вікна по 100 з сервера, прокрутка на висоту екрана; `hooks/use-windowed-list` і `hooks/use-row-selection` ставлять шаблони списку, лише з таблицею — `--add`), малий — `rows` + `pagination`. Колонки — `DataTableColumn` один раз для гріда й карток: `priority` і `overflow` (`keep` / `wrap` / `hide`) на вузькому екрані, `sortField` (сортування на сервері), `card` (роль у картці), `sticky` для номера. Своїх `<table>`, віртуалізації, нескінченної прокрутки й карткових списків не пиши; оголошення для скрінрідера — `announce` з `lib/announce`.
- **Над списком** (ADR-0017) — `StatusTabs` (вкладки-статуси, лічильники `useListCounts`), `FilterBar` (пошук, фільтри `FilterDefinition`: `options`, `date-range`, `money-range`, `record` — запис із довідника сервера; чипи) і `SavedViewsMenu` + `useSavedViews` з `hooks/use-saved-views` (особисті види `/me/views`). Стан списку — лише `useListState` з `useSearchParams` роутера (передай `filters` і `defaults.sortFields`: адреса — ввід ззовні): вкладка, фільтри, пошук, сортування й вид — в адресі синтаксисом API; таблицю рендер лише при `list.isReady`, у запит — `list.queryFilter`. Свого стану фільтрів у `useState`, localStorage для видів і окремого ендпоінта лічильників не пиши; у моках — `createSavedViewHandlers()`.
- **Масові дії й редагування в комірці** (ADR-0018) — вибір `useRowSelection([queryFilter, companyId])` і пропси `selection`, `rowLabel`, `bulkActions` у `DataTable` (колонку прапорців і панель вибраного таблиця додає сама); дія — фонова задача сервера: кнопка панелі й підтвердження — `useBulkAction` з `erp/bulk-action` (ADR-0066: право ролі, кількість, причина одна на всі через `reason`, запуск і прогрес у `showJobProgress`), `bulk.dialog` — на сторінці поруч зі списком; напряму — `dataProvider.startBulk(resource, action, toBulkSelection(state, queryFilter), { reason })`. Дія графа документа масово — без версії, з поточного статусу кожного запису. Редагування в комірці — `EditableCell` (оптимістично, відкат із поясненням), збереження — `useUpdate` `pessimistic` з `returnPromise: true` і `version`, кілька комірок одного запису — по черзі з версією попереднього. Масових дій циклом `PATCH` із клієнта, свого опитування задач і своїх «чекбокс-колонок» не пиши; у моках — `createBulkHandlers` (переходи документа — `bulkTransitionActions`, видалення — `{ remove: true }`) і `createJobHandlers`.
- **Сторінка списку** (ADR-0022) — шаблон `ListReport` з `templates/list-report`: `const report = useListReport({ resource, params, onParamsChange, defaults, tabs, filters })` (параметри — `useSearchParams` роутера; `tabs`, `filters`, `defaults` — у `useMemo`), далі `<ListReport report={report} title columns tableLabel … />` (`columns` — у `useMemo`, ключ рядка — `id` запису, інакше `getRowId`). Дії шапки й біля фільтрів — `actions` і `toolbar` як `{ id, node }`, масові — `bulk={{ actions: [{ id, render: (count) => … }], rowLabel }}` (дія з хуками — своїм компонентом у `render`) (вибір і фільтр для запиту — `report.selection`, `report.list.queryFilter`); великий список — `mode="scroll"`, малий — `mode="pages"`. Без `title` шапки в шаблоні немає: сторінка ставить `PageHeader` з `erp/page-header` сама (напр. над перевіркою сесії — тоді шапка не перемальовується; `ListReportHeader` — стара назва того самого компонента); сторінка без списку (налаштування, форма) теж бере `PageHeader`, не шаблон списку. Дошка, календар чи картки тих самих записів — подання (ADR-0091): `layouts` у `useListReport` (у `useMemo`), `{ id, label, icon: LAYOUT_ICONS.<table|cards> }` з `lib/icons`, без `component` — таблиця, з `component: Board` — свій вміст, що отримує `ListReportContentProps` (фільтр запиту, сортування, вибір, масові дії `bulkActions`, `isFiltered`, `onResetFilters`) і сам показує стани колекції; перемикач, адреса `?layout=` і збереження у виді — від шаблону. Свого перемикача подань і окремих вкладок, фільтрів і видів для дошки не пиши. Колонки, фільтри, вкладки й дії — лише списками з ключами (розширення модуля змінює їх за ключем, ADR-0020). Закріплення вгорі — `usePinColumn` з `erp/pin-toggle` у `columns` і `isPinned` (порядок дає сервер, у моках `pins: true`); розмір сторінки в `mode="pages"` запам'ятовується сам (`/me/list-settings`, у моках `createListSettingsHandlers()`) (ADR-0024). Своїх розкладок списку, джерел рядків, кнопок закріплення, вибору розміру й зв'язок вкладок, фільтрів і видів вручну не пиши.
