# erp-ui: Дані й моки

Довідка скіла `erp-ui` (імпорт і експорт, контракт, API й вхід, моки). Відкривай, коли задача зачіпає тему; правила ядра (`../SKILL.md`) діють і тут.

- **Імпорт і експорт** (ADR-0049) — `ImportWizard` з `erp/import-wizard`, `ExportDialog` з `erp/export-dialog`, вибір файла — `FileDrop` з `erp/file-drop`. Бібліотеку `hucre` напряму не імпортуй: лише через `lib/spreadsheet`, вона має лишатись окремим чанком.
- **Дані** лише через контракт модуля (`contract.ts`). Змінюєш контракт — оновлюєш моки (`mocks.ts`), fixtures і переклади в тому ж коміті.
- **Сервер на TypeScript** (ADR-0093) бере схеми й правила з чистого шару: `contract.ts`, `resources.ts` модулів і утиліти з розділу «Чистий шар контрактів» каталогу, лише `zod`. Свій файл, який бере сервер, імпортує з кіта лише файли шару: `@/lib/format-core`, `@/lib/statuses-core`, а не `@/lib/format` чи `@/lib/statuses`. Дані розширення для сервера — окремим файлом без компонентів (посібник, «Сервер на TypeScript»).
- **API й вхід** — за ADR-0002/0003 кіта: `createApiClient` + `createDataProvider` + `createAuthProvider` (пакунок `data`), хуки ra-core (`useGetList`, `useUpdate`, `useCanAccess`, `useAuthenticated`), профіль — `useMe()`. `CoreAdminContext`, хуки й типи ra-core (`RaRecord`) імпортуй з `@/lib/ra-core` (шов кіта, ADR-0090), а не з `ra-core`; ім'я, якого там немає, бери напряму й назви у звіті: його варто додати в шов. Фільтри — плоскі (`status`, `amount_gte`, `q`), збереження — з `version`, 409 → `ConflictDialog`, текст помилки — `useApiErrorMessage`. Свого fetch-шару не пиши.
- **API платформи** (ADR-0092) — `authProvider.account`, `.audit`, `.roles`… з `lib/platform-api`; більшість вантажить код при першому виклику. Свій API проекту, якого перший екран не потребує, — через `lazyApi` звідти ж, а не статичним імпортом у провайдер. Переклад рядка `{ uk, en }` — `localizedText` з `@/lib/localized-text`, не з `lib/auth`: так компонент не тягне вхід і всі API.
- **Моки** — `createResourceHandlers` / `createPlatformHandlers` з `lib/mocks` (пакунок `mocks`), сценарії перемикає `DevPanel`; кожен екран перевір у всіх семи сценаріях. Обробники — лише в `src/mocks/`, старт і `DevPanel` — під `import.meta.env.VITE_BACKEND === "mocks"` з `import()` (ADR-0079): `vite.config.ts` дає моки в розробці без змінної й зупиняє збірку без `VITE_BACKEND`; стала з окремого файла чи обробники поза текою тягнуть MSW у продакшн (посібник, розділ 5, «Моки поза продакшном»).
