# erp-ui: Форми

Довідка скіла `erp-ui` (форма й форма запису, дати й суми, майстер, оформлений текст, ідентифікатори, повторювані рядки, вибір запису). Відкривай, коли задача зачіпає тему; правила ядра (`../SKILL.md`) діють і тут.

- **Форми** (ADR-0015) — react-hook-form + zod (`mode: "onTouched"`, схема з `t` у `useMemo`) і `erp/form`: `FormField`, `FormErrorSummary`, `UnsavedChangesGuard`; поле — лише `FormField` (легке з'єднання `useFieldController`, ADR-0063: поле читає й перемальовує лише свій стан), `Controller` напряму не бери, особливо в рядках; «Зберегти» не вимикається (`disabled={isSubmitting} focusableWhenDisabled`), кнопки форми — `onMouseDown={keepFieldFocus}` (інакше перший клік губиться, ADR-0027), 422 → `setError(name, { type: "server" })`. Зразок — `ProfileForm`. Форма запису модуля (створення й зміна) — `RecordFormDialog` з `erp/record-form` і `useRecordForm` з `hooks/use-record-form` (ADR-0026): `POST` усіх полів, `PATCH` лише змінених з `version`, 409 — порівняння полів (запис розбирай схемою контракту з полями розширення), 422 — біля полів, «Закрити без збереження?»; поля — `RecordFormItem` з ключами (ключ — ім'я поля), вибір зі списку — `FormSelect` з `erp/form-select`; діалог форми в сторінці — лінивим чанком (`lazyWithPreload` + `whenIdle`, ADR-0009). Елемент вкладеної колекції запису (адреса, рахунок, ADR-0028) — та сама форма: `PATCH` запису з усією колекцією й `version`, `toPayload(values, keys, target)` застосовує зміну до `target` (після «Зберегти мої зміни» — збережений зараз), `fieldOfServerError` — поле форми для `bankAccounts.1.iban`; `id` нового елемента дає сервер; у моках — `detailFields` і `auditValue` у `createResourceHandlers`. Своїх зв'язок збереження, конфлікту й помилок сервера не пиши.
- **Дати, суми, підтвердження** (ADR-0015): `DateInput` / `DateRangeInput` / `TimeInput` (значення `"YYYY-MM-DD"`, текст помилки — `useDateIssueText`; у форму — `ref={field.ref}`), `MoneyInput` / `NumberInput`, сума прописом — `amountInWords`; зворотна дія — `useUndoToast`, видалення — `ConfirmDialog` (кнопка-наслідок, для критичного — `confirmWord`). Своїх календарів, масок дат і діалогів «Ви впевнені?» не пиши.
- **Майстер** (ADR-0043) — шаблон `Wizard` з `templates/wizard` і `useWizard` з `hooks/use-wizard`: кроки, `onNext` (перевірка чи збереження, `false` лишає на кроці), `onFinish`, фінальний огляд `WizardReview`. Степер окремо — `erp/stepper`. Прогрес у браузері — `lib/wizard-progress`, якщо кроки не зберігає сервер.
- **Оформлений текст** (ADR-0052) — поле `RichTextField` з `erp/rich-text-field`, показ `RichTextView` з `erp/rich-text-view`, формат і чужі дані `toRichText` і `richTextSchema` з `lib/rich-text`. Текст зберігається JSON-документом, не HTML. Tiptap напряму не імпортуй: редактор має лишатись окремим чанком.
- **ЄДРПОУ, РНОКПП, ІПН ПДВ, IBAN, телефон** — компоненти `erp/ua-id-input` і `erp/phone-input`, перевірка — `validateUaId` / `validatePhone`, текст помилки — `uaIdIssueKey` + `useErpUiT`. Зберігаються без пробілів (телефон — E.164).
- **Повторювані рядки й довгі форми** (ADR-0047) — `erp/repeating-rows`, `erp/key-value-field` (`lib/key-value`), `erp/save-bar`, `erp/record-form-page`. Рядки не пиши на `useFieldArray` вручну; порядок лише кнопками, рядок повертається кнопкою в ньому ж. «Зберегти» довгої форми стоїть у `SaveBar` останнім у `<form>`.
- **Вибір запису й реквізити** (ADR-0023) — `erp/record-picker` (пошук на сервері, «Створити…» через `create.onCreate`, значення — `id`) і `erp/copyable-value` (показ значення з «Копіювати»). Кілька значень із короткого довідника (сегменти, теги) — `MultiSelect` з `erp/multi-select` (ADR-0027: значення — масив ключів, поки довідник вантажиться — `options` не задано, помилка — `error` + `onRetry`). Свого пошукового поля для зв'язку з іншим записом, своїх чипів-мультивиборів і своєї кнопки копіювання не пиши.
