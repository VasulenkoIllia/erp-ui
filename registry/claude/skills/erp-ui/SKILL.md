# erp-ui: як будувати інтерфейс

Цей проект побудований на приватному реєстрі **erp-ui**. Повна специфікація — `docs/erp-ui/SPEC.md` у клієнтському проекті або `docs/SPEC.md` у репозиторії erp-ui. Цей скіл — короткий робочий порядок; при сумніві відкривай відповідний розділ специфікації.

## Перед роботою
1. Визнач, до якого модуля (ID A1…T1, LC01…LC12) і якого шаблону сторінки (List Report, Object Page, Worklist, Overview, Wizard, Split/FCL, Board, Runner, Kiosk) належить задача.
2. Знайди в реєстрі потрібні компоненти: каталог `docs/erp-ui/CATALOG.md` або `npx shadcn@latest search VasulenkoIllia/erp-ui -q <що шукаєш>`. Перевір, що вже встановлено в `src/components/ui/`. Ставити й оновлювати — командою кіта (розділ «Встановлення й оновлення кіта» нижче): `node scripts/erp-ui-kit.mjs update <версія> --add <елемент>`, що зміниться — `--dry-run`. Залежності проекту команда не змінює: ставить лише відсутні з діапазоном кіта, версію поза діапазоном кіта лише називає.
3. Якщо компонента немає: **не пиши локальний аналог**. Опиши, чого бракує, і запропонуй додати його в реєстр erp-ui (UI-ID з SPEC §13 або новий). Локальна реалізація — лише якщо користувач явно погодився, з позначкою `// erp-ui: candidate for registry`.

## Правила під час роботи
- **Лише токени.** Кольори, відступи, радіуси, тіні, шрифти беруться з CSS-змінних тем (`--primary`, `--muted-foreground`, `--success-soft`…). Жодних hex/rgb у компонентах, жодних довільних значень Tailwind на кшталт `text-[#123]`.
- **Рух** (ADR-0009, SPEC §6.6) — лише функціональний (поява, розгортання, підсвітка зміни, прогрес) і лише з токенів: `duration-fast|base|slow`, `ease-standard|enter|exit`. Не `transition-all` і не `duration-200` / `ease-linear` — це ловить `check-tokens`. `prefers-reduced-motion` кіт обробляє сам.
- **Швидкість** (SPEC §18.5): відгук ≤ 200 мс, перший екран ≤ 2,5 с на телефоні (CPU ×4). Сторінки — лінивими чанками (`lazyWithPreload` з `lib/lazy`, не `React.lazy`) у `ErrorBoundary` з `erp/error-boundary`, fallback — `LoadingFallback` з `erp/page-state` (оголошує завантаження скрінрідеру), з попереднім завантаженням при наведенні; важке, що з'являється не одразу, — при відкритті; рядки інших мов — функцією в `createI18n`, перед рендером `await whenI18nReady(i18n)`.
- **Статуси** — бейдж `*-soft` + `*-foreground` + іконка + підпис; ніколи лише колір. Основний колір не використовується для статусів. Статус запису модуля — `StatusBadge` з `erp/status-badge` і тон `StatusTone` (`lib/statuses`): схему й варіанти з урахуванням розширення дають `statusSchema` і `useResolvedStatuses` (ADR-0025).
- **Стани.** Кожен екран із даними має стани SPEC §8.1: скелетон, оновлення, порожньо вперше, нічого не знайдено, помилка з повтором, немає доступу, офлайн, застарілі дані, масова операція, блокування, конфлікт. Порожній стан не підміняє помилку.
- **Права.** Розділ без доступу — прихований (`PermissionGate`); дія без прав — неактивна з поясненням: `DeniedAction` з `erp/permission-gate` (причина в підказці й для скрінрідера), поки права невідомі — нічого. Поля без прав — read-only, не disabled.
- **Форми** (ADR-0015) — react-hook-form + zod (`mode: "onTouched"`, схема з `t` у `useMemo`) і `erp/form`: `FormField`, `FormErrorSummary`, `UnsavedChangesGuard`; «Зберегти» не вимикається (`disabled={isSubmitting} focusableWhenDisabled`), кнопки форми — `onMouseDown={keepFieldFocus}` (інакше перший клік губиться, ADR-0027), 422 → `setError(name, { type: "server" })`. Зразок — `ProfileForm`. Форма запису модуля (створення й зміна) — `RecordFormDialog` з `erp/record-form` і `useRecordForm` з `hooks/use-record-form` (ADR-0026): `POST` усіх полів, `PATCH` лише змінених з `version`, 409 — порівняння полів (запис розбирай схемою контракту з полями розширення), 422 — біля полів, «Закрити без збереження?»; поля — `RecordFormItem` з ключами (ключ — ім'я поля), вибір зі списку — `FormSelect` з `erp/form-select`; діалог форми в сторінці — лінивим чанком (`lazyWithPreload` + `whenIdle`, ADR-0009). Елемент вкладеної колекції запису (адреса, рахунок, ADR-0028) — та сама форма: `PATCH` запису з усією колекцією й `version`, `toPayload(values, keys, target)` застосовує зміну до `target` (після «Зберегти мої зміни» — збережений зараз), `fieldOfServerError` — поле форми для `bankAccounts.1.iban`; `id` нового елемента дає сервер; у моках — `detailFields` і `auditValue` у `createResourceHandlers`. Своїх зв'язок збереження, конфлікту й помилок сервера не пиши.
- **Дати, суми, підтвердження** (ADR-0015): `DateInput` / `DateRangeInput` / `TimeInput` (значення `"YYYY-MM-DD"`, текст помилки — `useDateIssueText`; у форму — `ref={field.ref}`), `MoneyInput` / `NumberInput`, сума прописом — `amountInWords`; зворотна дія — `useUndoToast`, видалення — `ConfirmDialog` (кнопка-наслідок, для критичного — `confirmWord`). Своїх календарів, масок дат і діалогів «Ви впевнені?» не пиши.
- **Списки й таблиці** (ADR-0016) — лише `DataTable` з `erp/data-table`: великий список — `list={useWindowedList(resource, { sort, filter })}` (вікна по 100 з сервера, прокрутка на висоту екрана), малий — `rows` + `pagination`. Колонки — `DataTableColumn` один раз для гріда й карток: `priority` і `overflow` (`keep` / `wrap` / `hide`) на вузькому екрані, `sortField` (сортування на сервері), `card` (роль у картці), `sticky` для номера. Своїх `<table>`, віртуалізації, нескінченної прокрутки й карткових списків не пиши; оголошення для скрінрідера — `announce` з `lib/announce`.
- **Над списком** (ADR-0017) — `StatusTabs` (вкладки-статуси, лічильники `useListCounts`), `FilterBar` (пошук, фільтри `FilterDefinition`: `options`, `date-range`, `money-range`, `record` — запис із довідника сервера; чипи) і `SavedViewsMenu` + `useSavedViews` з `hooks/use-saved-views` (особисті види `/me/views`). Стан списку — лише `useListState` з `useSearchParams` роутера (передай `filters` і `defaults.sortFields`: адреса — ввід ззовні): вкладка, фільтри, пошук, сортування й вид — в адресі синтаксисом API; таблицю рендер лише при `list.isReady`, у запит — `list.queryFilter`. Свого стану фільтрів у `useState`, localStorage для видів і окремого ендпоінта лічильників не пиши; у моках — `createSavedViewHandlers()`.
- **Масові дії й редагування в комірці** (ADR-0018) — вибір `useRowSelection([queryFilter, companyId])` і пропси `selection`, `rowLabel`, `bulkActions` у `DataTable` (колонку прапорців і панель вибраного таблиця додає сама); дія — фонова задача сервера: `dataProvider.startBulk(resource, action, toBulkSelection(state, queryFilter))` і `showJobProgress({ jobId, title })`, підтвердження з кількістю — `ConfirmDialog` на сторінці. Редагування в комірці — `EditableCell` (оптимістично, відкат із поясненням), збереження — `useUpdate` `pessimistic` з `returnPromise: true` і `version`, кілька комірок одного запису — по черзі з версією попереднього. Масових дій циклом `PATCH` із клієнта, свого опитування задач і своїх «чекбокс-колонок» не пиши; у моках — `createBulkHandlers` і `createJobHandlers`.
- **Сторінка списку** (ADR-0022) — шаблон `ListReport` з `templates/list-report`: `const report = useListReport({ resource, params, onParamsChange, defaults, tabs, filters })` (параметри — `useSearchParams` роутера; `tabs`, `filters`, `defaults` — у `useMemo`), далі `<ListReport report={report} title columns tableLabel … />` (`columns` — у `useMemo`, ключ рядка — `id` запису, інакше `getRowId`). Дії шапки й біля фільтрів — `actions` і `toolbar` як `{ id, node }`, масові — `bulk={{ actions: [{ id, render: (count) => … }], rowLabel }}` (дія з хуками — своїм компонентом у `render`) (вибір і фільтр для запиту — `report.selection`, `report.list.queryFilter`); великий список — `mode="scroll"`, малий — `mode="pages"`. Без `title` шапки в шаблоні немає: сторінка ставить `ListReportHeader` сама (напр. над перевіркою сесії — тоді шапка не перемальовується). Колонки, фільтри, вкладки й дії — лише списками з ключами (розширення модуля змінює їх за ключем, ADR-0020). Закріплення вгорі — `usePinColumn` з `erp/pin-toggle` у `columns` і `isPinned` (порядок дає сервер, у моках `pins: true`); розмір сторінки в `mode="pages"` запам'ятовується сам (`/me/list-settings`, у моках `createListSettingsHandlers()`) (ADR-0024). Своїх розкладок списку, джерел рядків, кнопок закріплення, вибору розміру й зв'язок вкладок, фільтрів і видів вручну не пиши.
- **Картка запису** (ADR-0019) — шаблон `ObjectPage` з `templates/object-page`: `back` (посилання до списку зі станом переходу, що повертає фільтри), `header={record && { title, status, fields: [{ id, label, value }], actions: [{ id, node }] }}` (h1 — `RecordHeader`, ціль `headingRef`; без запису `header` не передається — h1 прихований `title`), `statusBar` — `RecordStatusBar` з `erp/record-header`, `sections={[{ id, title, content }]}`, стрічка — `aside` (праворуч чи вкладкою за шириною контейнера). Дані — `useGetOne` з `meta` компанії: шапка одразу з кешу списку, детальний запис (рядки документа) — з `GET /<ресурс>/:id`; помилку запису передавай у `ObjectPage` лише коли запису немає, інакше це стан секції. Фокус після переходу — `useFocusHeadingOnNavigation(heading, location.pathname, ready)` з `hooks/use-focus-heading` (і для списку). Багато розділів — `tabs={{ value, onValueChange }}` (вибрана — в адресі `?tab=` із `replace`, змонтована лише вибрана вкладка, ADR-0024). Своїх розкладок картки, вкладок, смуг етапів і «Назад» через `history.back()` не пиши; у моках — опція `detail` у `createResourceHandlers`.
- **Модуль під клієнта** (ADR-0020) — файли модуля (`src/modules/<ID>-…`) у проекті не правиш: усе, чим клієнт відрізняється, — у файлі розширення проекту `src/extensions/<ID>-<назва>.ts` (компоненти слотів — поруч у `.tsx`), який модуль отримує там, де його підключають (маршрути, моки). Розширення — дані з ключами (`lib/extensions`): `add` з місцем `place` (`"start"`, `"end"`, `{ before }`, `{ after }`), `hide`, `move`; нові поля — `ExtensionField` (тип, підпис `{ uk, en }`, `required`, `mockValues`; `lib/extension-fields`); зв'язок з іншим записом сервера (відповідальний із користувачів, менеджер) — `type: "record"` з `resource` і `labelField`, а не список імен у коді: колонка, шапка, форма й фільтр самі показують назву з сервера (ADR-0030); колонки й поля шапки — за ключем поля, секції й дії картки — компоненти з `{ record, resource }` (`RecordSlotProps` з `templates/object-page`; поле розширення — `extensionValue(record, id)`), дія з `access` (`"edit"`) — лише з правом. Змінити властивість елемента модуля без заміни — `change: [{ id, … }]` (назва, ширина, пріоритет колонки; підпис і підказка поля форми; ADR-0026): заміна через `add` з ключем модуля забирає й вміст, і оновлення модуля до нього не доходять. Ключі модуля в змінах перевіряє TypeScript; закріплені (`locked`) не ховаються й не замінюються, але `change` діє й на них. Модуль зливає їх зі своїми (`applyKeyedChanges`, `useExtensionFields`, `useRecordSlots`) і розбирає запис схемою `extendSchema`. Бракує точки розширення — пропонуй її в кіт (PR в erp-ui), а не правку модуля. Зразок — `apps/demo/src/extensions/K2-invoices.ts`. Об'єкти розширення оголошуй з типом (`const organizations: OrganizationsExtension = {…}` чи `satisfies`): тоді після несумісного оновлення (мажорна версія) TypeScript покаже кожне місце у файлі розширення, а правиш лише його — за розділом «Як оновити розширення» в `CHANGELOG.md` кіта; об'єкт без типу зі старим ключем TypeScript може пропустити мовчки.
- **Модуль у проекті** (ADR-0025) — `node scripts/erp-ui-kit.mjs update <версія кіта> --add modules/<ID>-<назва>` ставить файли модуля в `src/modules/<ID>-<назва>/` як є (кіт вони імпортують шляхами проекту `@/components/…`, `@/lib/…`, `@/hooks/…` — псевдоніми `shadcn init` не змінюй) і спільні компоненти, яких бракує. Підключення — фабрика один раз: `const contactsModule = createContactsModule({ basePath: "/crm", extension })` → `routes` (у `useRoutes` під `Suspense` і межею помилок застосунку), `nav` (підпис — `localizedText(item.label, language)`), `resources` (права й сценарії моків), `preload(pathname)`; моки — `createContactsMocks({ extension: <файл полів> }).handlers`. Розширення модуля, крім полів, колонок, секцій і дій: `filters` і `tabs` (з поля-списку, так/ні чи дати; вкладка — `{ id, label, filter }`), `statuses` (додати з `tone` і `mockEvery`, сховати з вибору, `change` — підпис, тон чи іконка статусу модуля без заміни), `detailRows: { hide }` (рядки «Подробиць» картки) і `history: false` (картка без журналу) — для бекенду, якому бракує полів чи журналу змін; типи `Contact`, `Organization`, `ExtensionField` — з індексу модуля, `strings: { uk, en }` (перевизначення рядків модуля за ключами його `i18n/*.json`), `form` (поле розширення у формі модуля — `add` з місцем, `description`, `wide`; обов'язкове поле мусить бути у формі; `change` — підпис чи підказка поля модуля). Рядки модуля — свій простір імен, реєструвати не треба. Зразок — `apps/demo/src/extensions/B1-contacts.ts` і `registry/modules/B1-contacts/README.md`. Модуль A2 «Користувачі й ролі» — `createUsersModule({ basePath, extension, homePath })` (список і картка людини, сторінка «Ролі й права» `<basePath>/roles`; `homePath` — куди після «Увійти як…»; пункт `nav` з `access` показуй лише з цим правом), моки — `createUsersMocks`, колеги для мок-сервера входу — `createUsersFixtures` (ADR-0031); розширення — `users` (`fields`, `columns`, `filters`, `tabs`, `recordFields`, `sections`, `actions`, `history`) і `roles: { page: false }` (без сторінки ролей).
- **Адаптив.** Контейнерні запити (`@container`). Таблиця на телефоні → картки; фільтри й піккери → нижня шторка; канбан → одна колонка + «Перемістити в…». Перевір 360, 768 і 1440 px.
- **Доступність.** WCAG 2.2 AA: справжні `button`/`a`/`label`, `aria-label` для кнопок-іконок, альтернатива кожному перетягуванню, цілі ≥ 24 px (≥ 44 px у звичайній щільності), фокус не перекривається.
- **Тексти** лише через i18n (uk + en): рядки проекту — у JSON його просторів імен, рядки кіта — `useErpUiT()`; множина `_one/_few/_many/_other` (en — `_one/_other`); без фіксованих ширин для тексту. Мова за замовчуванням — українська.
- **Числа, суми й дати** — лише `useFormat()` з `@/lib/format`: гроші — мінорні одиниці + код валюти («48 600,00 ₴», інші валюти кодом), дати — явні стилі (`date`, `long`, `monthYear`…), календарні дати — рядком `YYYY-MM-DD`. Ніяких `toLocaleString`, `DD.MM.YYYY`, ручних «грн».
- **Оболонка** — лише `erp/app-shell` (+ `command-palette`, `user-menu`, `company-switcher`, `notification-bell`); вигляд і мову змінює `lib/appearance` (`useAppearance`), не прямі атрибути `<html>`. Застосунок збирай із частин кіта (ADR-0029), а не пиши свої: `SessionGate` з `erp/app-gate` навколо оболонки (гість, спінер, помилка профілю з повтором, `SessionGuard`), екрани входу — `createAuthRoutes` з `erp/auth-routes` поза брамою, вихід у меню — `useSignOut()`, `QueryClient` — `createQueryClient()` з `lib/query-client` (повторів не налаштовуй сам), стан замість сторінки — `PageState` з `headingLevel={1}` (фокус на заголовок ставить сам; поза оболонкою — у `PageStateMain`), свій екран з токеном із листа — `useEmailLinkToken` (токен не лишається в адресі; ADR-0030), список над карткою — крихта з `href`. e2e — помічники `e2e/erp-ui.ts` (`openAs`, `expectNoA11yViolations`, `expectNoHorizontalScroll`).
- **Іконки** — поняття → іконка лише зі словника `lib/icons` (модулі, статуси, дії); гривня — `HryvniaIcon`; товщину лінії задає `IconProvider`, не пропси окремих іконок.
- **Стани** — `PageState` / `PageSkeleton` з `erp/page-state`; тексти за замовчуванням уже перекладені.
- **ЄДРПОУ, РНОКПП, ІПН ПДВ, IBAN, телефон** — компоненти `erp/ua-id-input` і `erp/phone-input`, перевірка — `validateUaId` / `validatePhone`, текст помилки — `uaIdIssueKey` + `useErpUiT`. Зберігаються без пробілів (телефон — E.164).
- **Вибір запису й реквізити** (ADR-0023) — `erp/record-picker` (пошук на сервері, «Створити…» через `create.onCreate`, значення — `id`) і `erp/copyable-value` (показ значення з «Копіювати»). Кілька значень із короткого довідника (сегменти, теги) — `MultiSelect` з `erp/multi-select` (ADR-0027: значення — масив ключів, поки довідник вантажиться — `options` не задано, помилка — `error` + `onRetry`). Свого пошукового поля для зв'язку з іншим записом, своїх чипів-мультивиборів і своєї кнопки копіювання не пиши.
- **Дані** лише через контракт модуля (`contract.ts`). Змінюєш контракт — оновлюєш моки (`mocks.ts`), fixtures і переклади в тому ж коміті.
- **API й вхід** — за ADR-0002/0003 кіта: `createApiClient` + `createDataProvider` + `createAuthProvider` (пакунок `data`), хуки ra-core (`useGetList`, `useUpdate`, `useCanAccess`, `useAuthenticated`), профіль — `useMe()`. Фільтри — плоскі (`status`, `amount_gte`, `q`), збереження — з `version`, 409 → `ConflictDialog`, текст помилки — `useApiErrorMessage`. Свого fetch-шару не пиши.
- **Моки** — `createResourceHandlers` / `createPlatformHandlers` з `lib/mocks` (пакунок `mocks`), сценарії перемикає `DevPanel`; кожен екран перевір у всіх семи сценаріях.
- **Вхід і акаунт** — лише екрани пакунка `auth` (ADR-0010, ADR-0011, ADR-0012): `LoginScreen`, екрани відновлення, `SignUpScreen`, `SessionGuard`, форми `account-security`, `FactorsSection`, `SessionsSection`, `TrustedDevicesSection`, `SignInHistory`; що ввімкнено й бренд, вирішує `GET /auth/methods`. Чутливі дії — через `useReauth().guard`. «Увійти як…» — `useImpersonation` + `ImpersonationBanner` у слоті `banner` оболонки. QR — `erp/qr-code`, «Копіювати» — `erp/copy-button`. Своїх форм входу, налаштування 2FA й «повторіть пароль» не пиши.
- **Профіль і адміністрування доступу** (ADR-0012): `ProfilePhoto` + `ProfileForm` (фото обрізається в браузері, часовий пояс — `TimezoneSelect`), `ApiTokensSection`, `SecurityPolicyForm`, `RecoveryRequestsSection` + `useResetFactors`. Обов'язковий другий крок, термін пароля й дозволені адреси вхід виконує сам (`FactorSetupStep`). Пошук у списку — `ui/combobox`, повзунок — `ui/slider`.
- **Аудит, інтеграції, сповіщення, доступ** (ADR-0013): `AuditLog` (історія запису — `filter`), `WebhooksSection`, `NotificationSettingsForm`, `useUserAccessSheet` + `ActiveSessionsSection`. Журнал пише сервер; у моках зміни записів через `createResourceHandlers` потрапляють у журнал і вебхуки самі. Своїх журналів, сторінок вебхуків і блокування не пиши.
- **Сторінки модуля в кіті** (ADR-0025, ADR-0031) — спільні помічники, а не копії в теці модуля: `useExtendedList` (`hooks/use-extended-list`), `useCardRecord` (`hooks/use-card-record`), `usePageHeading`, `useHistoryRefresh`, `useTabParam` (вкладка картки в адресі), `RecordLink` і `BackToList` (`erp/record-link`), рядки з перевизначеннями — `moduleResources` (`lib/i18n-namespaces`); моки, що будують записи самі, — `filterMockRecords`, `sortMockRecords`, `registerMockRecords` (`lib/mocks`).
- **Команда й компанія** (ADR-0014): `RolesEditor` (ролі й матриця прав; каталог прав — з бекенда), `InvitationsSection`, `PermissionGate`, `InboxBell` у топбарі + `NotificationInbox`, `CompanyProfileForm` / `CompanyImages` / `CompanyBranchesSection`; палітра компанії — `useBrandAppearance(useCompanyProfile(Boolean(me)).data?.palette)`. Люди компанії — модуль A2 (ресурс `users`): довідник без `users:read` — лише `{ id, version, name, email }`, тож поле-запис на `users` показує імена всім у компанії; свого списку людей не пиши. Нові ресурси модуля — у каталог прав бекенда (і `permissionResources` моку), а не в UI. Ролі й права дають лише в межах своїх («стеля», ADR-0032): у `RolePicker`, `RoleMatrix`, `RoleDetail` передавай `ceiling={me.permissions}`, недоступне вони показують лише для перегляду з причиною (`readOnly`, у порядку Tab), а не `disabled`; ролі — компанії запиту (ADR-0033); дії над людиною — лише в компанії запиту; «стеля» доступу (ADR-0034) — вийти, завершити сесію, заблокувати, скинути другий крок лише людині, чиї права (в усіх її компаніях) маєш сам: свої кнопки доступу — з `{...useAccessCeiling(roleIds)}` (`erp/user-access-data`) у `UserAccessButtons` і `UserSessionsList`, а не власна перевірка; права в моках — у компанії запиту (`mockRequestPermissions`); перевірка запрошення — `POST /auth/invite/check`; запрошення (ADR-0035) — сторінка модуля A2 чи `InvitationsSection`, своєї не пиши: бекенд при перевірці й прийнятті перевіряє права автора запрошення (410), повтор робить автором того, хто повторив, повтор і відкликання — з «стелею» (403); «стеля» над списком ролей — `useRolesCeiling()` (`erp/user-access-data`). Сповіщення модуля — через бекенд у `/notifications`, власних дзвіників не роби.
- **Інтеграції** (доставка, ПРРО, банк, ЕДО, KSeF…): показуй нормалізований статус і сирий код провайдера; адреси, ставки й ліміти — дані з датою дії, не константи.
- **Встановлення й оновлення кіта** — лише командою кіта в проекті (ADR-0029): `node scripts/erp-ui-kit.mjs update <версія> --add <елемент>` (новий елемент), `update <версія> --dry-run` (що зміниться), `update <версія>` (оновити всі встановлені), `check` (файли кіта не правлені; у `pnpm lint`). `shadcn add` напряму не запускай: елемент не потрапить у `kit-files.json`, а модуль з приватного GitHub не встановиться. Файли `scripts/erp-ui-kit*.mjs`, `e2e/erp-ui.ts` і `kit-files.json` руками не правиш.
- **Компоненти з реєстру** не переписуй мовчки. Якщо змінюєш компонент спільного шару (`ui`, `erp`, `templates`, `lib`, `hooks`) — позначка `// erp-ui: local override — <причина>` і пропозиція перенести зміну в реєстр. Модулі не правиш узагалі — лише файл розширення (правило вище).

## Нова залежність
Додавай лише після перевірки чотирьох бар'єрів:
1. Ліцензія: MIT, Apache-2.0, BSD, ISC (без копілефту, SSPL, ELv2, Hippocratic, EPL, BSL).
2. Реліз за останні ~6 місяців і React 19 у peer-залежностях.
3. Працює з Vite і токенами Tailwind v4 без другого рантайму стилів.
4. Походження вендора відповідає політиці.

Звір із червоним списком у SPEC §5. Платні бібліотеки — лише за погодженням під конкретного клієнта.
