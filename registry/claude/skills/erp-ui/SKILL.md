# erp-ui: як будувати інтерфейс

Проект побудований на реєстрі **erp-ui**. Норма — `docs/erp-ui/SPEC.md` (у репозиторії кіта `docs/SPEC.md`), каталог елементів — `docs/erp-ui/CATALOG.md` (не читай цілком, шукай за назвою), опис модуля — `README.md` у `src/modules/<ID>-…/`. Тут ядро: порядок роботи й правила, що діють завжди. Подробиці теми — у довідках `references/` поруч із цим файлом.

## Порядок роботи
1. Визнач модуль (ID A1…T1, LC01…LC12) і шаблон сторінки (List Report, Object Page, Worklist, Overview, Wizard, Split/FCL, Board, Runner, Kiosk).
2. Прочитай довідки своєї задачі за таблицею нижче, усі, яких вона торкається.
3. Знайди елементи в каталозі чи `npx shadcn@latest search VasulenkoIllia/erp-ui -q <що шукаєш>`; що вже стоїть — у `src/components/`. Ставить і оновлює їх лише команда кіта (`references/kit.md`).
4. Збери екран із шаблону й елементів реєстру за правилами ядра й довідок.
5. Пройди «Перед здачею».

## Правила, що діють завжди
Після тире — чим правило перевіряється; «сам» означає, що автоматичної перевірки немає.
1. Інтерфейс лише з шаблонів і елементів реєстру, свого аналога не пиши — сам.
2. Лише токени тем: без hex, rgb, стандартної палітри й довільних розмірів Tailwind; рух лише з токенів — `node scripts/erp-ui-check-tokens.mjs`.
3. Статус — бейдж, іконка й підпис, ніколи лише колір — сам.
4. Кожен екран із даними має стани SPEC §8.1; порожній стан не підміняє помилку — сценарії моків.
5. Права вирішує сервер: розділ без доступу прихований, дія неактивна з причиною; правил запису сам не обчислюй — сценарій `forbidden`.
6. Суми, податки, номер, курс і ланцюг документів рахує сервер; у браузері лише `lib/document-totals` — сам.
7. Тексти лише через i18n (uk і en), числа й дати лише `useFormat()` — сам.
8. Дані лише через контракт модуля; контракт, моки, фікстури й переклади змінюються разом — `tsc`.
9. Файли кіта й модуля не правиш, відмінності клієнта — у файлі розширення — `node scripts/erp-ui-kit.mjs check`.
10. Ставиш і оновлюєш лише командою кіта, `shadcn add` напряму не запускаєш — `node scripts/erp-ui-kit.mjs check`.
11. Сторінки й важке — лінивими чанками через `lazyWithPreload` і обгортки кіта, не `React.lazy` — сам.
12. Адаптив через контейнерні запити: 360, 768 і 1440 px без горизонтальної прокрутки — `expectNoHorizontalScroll`.
13. WCAG 2.2 AA: справжні `button`, `a`, `label`, фокус видно, цілі від 24 px — `expectNoA11yViolations`.
14. Нова залежність — лише після чотирьох бар'єрів (`references/kit.md`) — сам.
15. Інтеграції: нормалізований статус і сирий код провайдера поруч — сам.

## Коли бракує компонента
**Не пиши локальний аналог.** Опиши, чого бракує, і запропонуй додати його в реєстр erp-ui (UI-ID з SPEC §13 або новий). Локальна реалізація — лише якщо користувач явно погодився, з позначкою `// erp-ui: candidate for registry`; файл кіта лишається як є.

## Перед здачею
- [ ] Екран зібраний із шаблону й компонентів реєстру.
- [ ] Усі стани є й перевірені через сценарії моків (`success`, `error`, `empty`, `slow`, `conflict`, `forbidden`, `offline`).
- [ ] 360 / 768 / 1440 px; світла й темна тема; Сапфір і Графіт; звичайна й компактна щільність.
- [ ] uk і en без «зламаних» рядків; числа 1, 2, 5, 11, 21, 22, 25, 101 у множині (SPEC §11).
- [ ] Клавіатура: усе досяжне, фокус видно; axe без порушень.
- [ ] Типи без помилок, тести зелені; `node scripts/erp-ui-check-tokens.mjs` і `node scripts/erp-ui-kit.mjs check` проходять.
- [ ] Новий загальний компонент запропоновано до реєстру erp-ui.

У звіті користувачу коротко: що зроблено, які компоненти реєстру використано, що запропоновано додати в реєстр.
