# 0006. Узгодженість: зовнішні компоненти перебудовуємо

- Статус: прийнято
- Дата: 13.10.2026
- Хто ухвалив: власник

## Контекст

Кіт збирається з кількох джерел: shadcn/ui, ReUI, Dice UI, Shadcn Admin Kit, Kibo UI (як код). У кожного свої висоти, відступи, фокус, іконки й обробка станів. Якщо брати їх «як є», інтерфейс виглядатиме зібраним із різних наборів. Власник вимагає однорідну систему.

## Рішення

1. **Зовнішній компонент не потрапляє в реєстр «як є».** Перед додаванням його переводять на примітиви `registry/ui` і токени erp-ui. Оновлення з оригіналу переносимо вручну, з переглядом диффу.
2. **Систематичні правки — скриптом** `scripts/adapt-upstream.mjs` (покритий тестами), щоб повторювати їх при кожному оновленні з upstream:
   - фокус: суцільне кільце 2 px `--ring` замість напівпрозорого 3 px (контраст ≥ 3:1);
   - текст помилок: `text-destructive` → `text-destructive-foreground` (≥ 4.5:1);
   - підкладка модалок: `bg-black/10` → токен `bg-overlay`, без розмиття;
   - довільні розміри й кольори → шкала Tailwind або токени;
   - `cn` → `@/registry/lib/utils` (знає утиліти щільності).
3. **Ручні правки** позначаються коментарем `// erp-ui: …` з причиною:
   - висоти контролів і рядків — з токенів щільності (`h-control`, `size-control`, `h-row`);
   - зона натиску ≥ `--touch-min` без збільшення контрола (`touch-target`);
   - статуси — soft-тло + `*-foreground` (варіанти `success`, `warning`, `info`, `destructive`);
   - read-only відрізняється від disabled і лишається у фокусі;
   - тексти інтерфейсу — параметри з українським значенням за замовчуванням (до i18n на кроці 0.3);
   - жодних залежностей від Next.js (`next-themes` → `useResolvedTheme`).
4. **Шапка походження** в кожному файлі: `// erp-ui: основа — <джерело>/<компонент> (<версія>, <дата>)`.
5. **Автоматичні запобіжники в CI:**
   - стандартну палітру Tailwind вимкнено (`registry/tokens/no-default-colors.css`);
   - `scripts/check-tokens.mjs` не пропускає сирі кольори й довільні розміри (виняток — коментар `erp-ui: allow-raw-value — <причина>`);
   - `pnpm check:contrast` — 370 пар контрасту в усіх палітрах і темах;
   - axe (WCAG 2.2 AA) на сторінках демо у 5 палітрах × 2 темах × 2 щільностях;
   - ESLint з `jsx-a11y-x` (strict).
6. **Іконки — лише lucide**, обведення й розмір — однакові в усьому реєстрі.

## Наслідки

- Оновлення з upstream коштують ручної роботи, але вона передбачувана: свіжий файл → `adapt-upstream` → дифф із нашою версією → перенести нове, зберігши правки `erp-ui:`.
- Клієнтські проекти беруть усе з одного місця (наш реєстр), тож однорідність переноситься в проекти без додаткових зусиль.

## Розглянуті варіанти

- «Лише перефарбувати» (кольори й радіус) — легше оновлювати, але розбіжності в розмірах, відступах і поведінці лишаються. Відхилено власником.
