# 0099. Легкий набір: свій сервер і свій вхід проекту

- Статус: прийнято (змінює ADR-0021 п. 1; доповнює SPEC §1, ADR-0004, ADR-0010, ADR-0015, ADR-0016 і ADR-0026)
- Дата: 24.11.2026
- Хто ухвалив: власник, 15.11.2026 (кіт офіційно підтримує свій сервер і свій вхід проекту: вхід за логіном, таблиця й
  вибір без бібліотеки даних, розділ посібника, тестовий проект у CI) і 24.11.2026 (вікторина старту кроку: окрема легка
  форма входу, повний екран входу без змін; форма нового пароля за посиланням у цьому ж кроці; поле форми — окремим
  легким елементом); назви елементів, типів і переліку — уточнення в кроці за наявними зразками кіта

## Контекст

- Кіт збудовано під свій контракт: ресурси й помилки ADR-0002, сесія й профіль ADR-0003. Новий бекенд пишеться під
  нього (ADR-0021 п. 1), вхід і брама сесії йдуть через провайдер входу на ra-core, а вхід паролем знає лише email.
- Малий застосунок часто має свій сервер: свій формат помилок, сесію в cookie, дві-три ролі замість прав
  `<ресурс>:<дія>`, вхід логіном, запрошення й скидання пароля посиланням від адміністратора. Модулі кіта йому не
  потрібні, а вигляд, оболонка, стани, таблиця, поля й вхід — потрібні.
- Збирач реєстру йде за всіма імпортами, також за `import type` (ADR-0004): файл має їхати разом з елементом, інакше
  проект не скомпілюється. Тож `erp/data-table` через тип сортування й великого списку, а `erp/form-select` через тип
  пропсів поля з `erp/form` ставили проекту ra-core, роутер і react-hook-form, хоча в збірку їхній код не йшов. Поле
  форми тягнуло ra-core, бо в тому самому файлі жив захист незбережених змін, якому потрібен роутер ra-core.

## Рішення

1. **Свій сервер і свій вхід — офіційно (змінює ADR-0021 п. 1).** Проект, що бере модулі, шар даних чи вхід кіта,
   пише бекенд під контракт кіта або підключає наявний через адаптер, як і раніше. Проект без них може мати свій API й
   свій вхід: тоді він бере лише легкий набір (п. 2), а запити, сесію, помилки й права пише сам. Модулі згодом —
   сервер під контракт чи адаптер (ADR-0021 п. 2–6).
2. **Легкий набір** — перелік `LIGHT_SET` у `registry/registry.config.mjs` і всі `ui/*`: `base`, оболонка й меню
   користувача, заголовок, стани сторінки й межа помилок, таблиця, поле форми, вибір, дата, число, мультивибір, файл,
   підтвердження, статус, копіювання, картка й форми входу, поле пароля. Жоден не тягне ra-core і react-router, зокрема
   типами: `pnpm check:registry` зупиняє елемент набору з такою залежністю. Новий елемент набору — запис у переліку;
   каталог має розділ «Легкий набір».
3. **Чисті частини — окремими файлами, старі шляхи лишаються.** Імпорти зі старих шляхів працюють як були.
   - `lib/data-table-core`: тип сортування `DataTableSort` (та сама форма, що `SortPayload` ra-core, тож проект на
     ra-core передає своє сортування як є) і великого списку `WindowedList`; `lib/row-selection`: тип вибору рядків
     `RowSelection`. Хуки `use-windowed-list` і `use-row-selection` реекспортують свої типи.
   - `erp/form-field`: `FormField`, `FormErrorSummary`, `keepFieldFocus`; `erp/form` реекспортує їх і має
     `UnsavedChangesGuard`. Тип пропсів поля `FormControlProps` — `lib/form-control`, без react-hook-form.
   - `erp/password-field`: поле пароля й смужка надійності з мінімумом проекту; `erp/password-input` бере мінімум із
     політики сервера кіта. `erp/auth-card`: картка екрана входу, бічна панель — лише від `@5xl`; `AuthLayout` додає
     до неї бренд. `hooks/use-countdown`: відлік секунд для повтору коду й «Забагато спроб».
4. **Вхід для свого сервера — `erp/login-form`.** Повний екран входу кіта (`erp/login-screen`) не змінюється.
   - `LoginForm`: перше поле — логін (за замовчуванням) чи email; запит робить проект у `onSubmit({ identifier,
     password })`, після успіху сам переходить далі. Значення — з полів форми (`name`: `username`, `password`), тож
     автозаповнення без події введення теж іде. Порожні поля — помилка біля поля й фокус на першому, запит не йде;
     введення знімає помилку. Повторне натискання, поки запит іде, нічого не відправляє; після успіху форма лишається
     зайнятою, поки проект переходить далі (одноразове посилання не витрачається двічі).
   - Причину відмови проект будує з відповіді свого сервера — `AuthFormFailure`: `credentials`, `rateLimited`
     (`retryAfterSeconds` із заголовка `Retry-After`), `linkInvalid`, `offline`, `server` або `message` зі своїм
     текстом мовою інтерфейсу. Текст сервера іншою мовою людині не показуємо. Кинутий (також синхронно) `TypeError`
     (збій `fetch`) — `offline`, будь-яка інша помилка — `server`; сама помилка — у консолі. Невідома причина чи
     порожній `message` — `server`: людина не лишається без відповіді.
   - «Забагато спроб» із секундами до години: кнопка недоступна з відліком і лишається у фокусі, далі доступна сама,
     а текст відмови зникає. Без секунд чи довше за годину — «Спробуйте пізніше», кнопка доступна.
   - `SetPasswordForm`: новий пароль за посиланням запрошення чи скидання — «Показати пароль», підказка надійності,
     `minLength` проекту (за замовчуванням — типовий кіта), закороткий — помилка біля поля. Токен із посилання
     (`#токен`) проект читає один раз, прибирає з адреси й надсилає лише в тілі запиту (посібник).
   - Сторінку дає `AuthCard`; логотип, підвал і бічну панель передає проект.
5. **`FormSelect` без форми й з числами.** Значення — `string | number | null`: що в `items`, те й приходить в
   `onValueChange`, без перетворень. Поза `FormField` список називає `aria-label` чи `aria-labelledby` замість `id`:
   тип вимагає одне з трьох, тож список без доступної назви не скомпілюється.
6. **Базовий шлях.** Елементи набору не мають абсолютних адрес: ассети, шрифти й ліниві чанки (англійські рядки)
   ідуть від `base` Vite, посилання оболонки — через `renderLink` роутера проекту з його `basename`.
7. **Перевірка в CI** — задача «легкий набір» (`pnpm light-smoke`): чистий проект Vite зі своїм роутером ставить `base`
   і `LIGHT_SET` командою кіта цього коміту, як у посібнику. Кіт не ставить ra-core і моки й не чіпає роутер проекту;
   typecheck і збірка з `base: "/new/"`, адреси збірки під `/new/`; у Chromium — вхід логіном, оболонка й таблиця,
   перемикання на англійську, новий пароль за посиланням із токеном у `#`, шрифт завантажено, жодного запиту з
   помилкою.

## Наслідки

- SPEC §1 («Що не входить: бекенд») — або під контракти кіта, або свій сервер проекту з легким набором.
- Легкий проект не має модулів кіта, брами сесії, автовиходу, «Увійти як…» і вподобань на сервері: це він пише сам
  або переходить на контракт. i18next, мова інтерфейсу за вибором людини, оновлення лише в чисте дерево, `@page` кіта
  й розмір поля лишаються як були (SPEC §3.3, §6.5, §11; ADR-0062): цим рішенням не змінюються.
- Поза набором абсолютна адреса лишається у фонового файла push (`/erp-ui-push-sw.js`, ADR-0046): проекту з `base` не `/`
  він поки не підходить.
- Зміна сумісна: нові елементи й необов'язкові пропси, типи переїхали з реекспортом зі старих шляхів (мінорна версія).

## Розглянуті варіанти

- **Логін і в повному екрані входу кіта** (вид першого поля з `GET /auth/methods`): відхилено вікториною — проекту з
  сервером під контракт кіта, якому потрібен логін, ще немає, а зміна контракту входу (ADR-0003, ADR-0010) без нього
  не перевіряється.
- **Лише посібник, без переліку й перевірки:** відхилено — новий `import type` знову непомітно поставив би проекту ra-core.
- **Окремі легкі копії елементів:** відхилено — два варіанти одного компонента розходилися б; легка частина виноситься
  з елемента, а повний її реекспортує.
- **Проект пише вхід сам із `ui/*`:** відхилено вікториною — кожен проект зі своїм входом повторював би стани
  відмови, відлік і доступність форми.
