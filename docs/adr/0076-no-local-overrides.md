# 0076. Файли кіта в проекті не правляться: позначки `local override` більше немає

- Статус: прийнято (змінює SPEC §3.3 і §19, ADR-0004 п. 8 і ADR-0020 п. 6–7; доповнює ADR-0029)
- Дата: 11.11.2026
- Хто ухвалив: власник, 11.11.2026 (рекомендований, найлегший варіант)

## Контекст

SPEC §3.3 і §19, ADR-0004, ADR-0020, скіл і посібник казали: правку файла спільного шару кіта (`ui`, `erp`, `templates`,
`lib`, `hooks`) у проекті позначають `// erp-ui: local override — <причина>`, «щоб не затерти». Команда кіта (ADR-0029)
позначки не читає:

- файл із відбитком у `kit-files.json`: будь-яка правка дає червоний `check` і зупиняє `update` до запису. Оновитись можна
  лише вручну — зберегти латку, повернути файл, оновити, накласти латку, — після чого `check` знову червоний, а він стоїть у
  `lint` проекту;
- файл без відбитка (маніфест загублено чи виправлено руками, перший `update --items` у проекті без маніфесту): `update`
  перезаписує правку без попередження.

Для модулів ADR-0020 уже заборонив правки: зміни під клієнта — у файлі розширення проекту.

## Рішення

1. **Локальних правок файлів кіта в проекті немає** — ні модулів (ADR-0020), ні спільних шарів. Потрібна зміна модуля —
   файл розширення проекту (ADR-0020). Бракує точки розширення чи можливості компонента — PR у кіт. Чекати не можна — свій
   компонент під іншою назвою в коді проекту (як «від'єднаний» модуль, ADR-0020 п. 7); файл кіта лишається як є.
2. Позначку прибрано зі SPEC §3.3 і §19, ADR-0004 п. 8, ADR-0020 п. 6–7, скіла й посібника.
3. **Захист для проектів, що діяли за старим правилом:** `update` перед записом шукає позначку `local override` у файлах,
   які перезаписує, і зупиняється зі списком цих файлів. Додає це наступний крок доставки команди кіта; до того файл із
   відбитком уже зупиняє `update` як змінений.

## Наслідки

- Проект із позначками переносить правки в розширення, у кіт чи у свій компонент і повертає файл кіта (`git checkout --
  <файл>` чи версія кіта).
- `check` у `lint` проекту лишається зеленим, бо файлів кіта ніхто не править.
- Версії: зміна норми без зміни API команди; рядок у `CHANGELOG.md`.

## Розглянуті варіанти

- **Команда підтримує локальні правки:** список `overrides` у маніфесті, `check` їх пропускає й показує окремим рядком,
  `update` робить тристороннє злиття й зупиняється на конфлікті. Новий код злиття, який треба підтримувати; найлегший
  варіант закриває проблему без нього.
- **Лишити позначку як є:** норма обіцяє захист, якого немає, а в одному шляху правка зникає тихо.
