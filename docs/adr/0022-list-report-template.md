# 0022. Шаблон List Report: список сутностей зі стану в адресі, елементи з ключами

- Статус: прийнято (доповнює ADR-0016, ADR-0017, ADR-0018 і ADR-0019; перший крок ADR-0020 у коді)
- Дата: 15.10.2026
- Хто ухвалив: власник (план хвилі 1, крок 1.1, `docs/WAVE-1.md`)

## Контекст

SPEC §7 описує List Report: заголовок і дії, вкладки-статуси, FilterBar із чипами, збережені види,
панель масових дій, таблиця (на телефоні — картки), пагінація. У хвилі 0 усі частини з'явились
окремо (ADR-0016–0018), а складала їх сама стрес-сторінка «Дані й моки»: власний виклик
`useSavedViews`, `useListState`, `useListCounts`, `useRowSelection`, власні джерела рядків (прокрутка
вікнами й сторінки) і розкладка. Новий список у модулі мусив би повторити все це.

Звіт хвилі 0 (розділ 6, критерій 1) і план пілота ставлять шаблон перед модулем B1: у B1 два списки
(контакти й компанії). ADR-0020 вимагає, щоб колонки, фільтри, вкладки й дії списку передавались
списками з ключами: розширення проекту додає, ховає чи переставляє елемент за ключем, не знаючи, як
модуль його будує.

## Рішення

1. **Елемент реєстру `templates/list-report`** (шар 4, `@components/templates`, як ADR-0019):
   - `useListReport({ resource, params, onParamsChange, defaults, tabs?, filters? })` — стан
     списку: адреса (`useListState`), особисті види (`useSavedViews`), лічильники вкладок
     (`useListCounts`), вибір рядків (`useRowSelection([queryFilter, companyId])`);
   - `ListReport` — розкладка й джерела рядків; `ListReportHeader` — шапка окремо: без `title`
     `ListReport` шапки не має, її ставить сторінка (поки перевіряється сесія, шапка вже на екрані
     й лишається тим самим вузлом; список у колонці FCL — без власного h1).
2. **Хук окремо від розкладки.** Сторінці потрібні вибір рядків і фільтр запиту для своїх масових
   дій і діалогів (погодження, зміна запису): вони беруться з результату хука, а не з контексту
   шаблону. Шаблон не вибирає роутер: `params` і `onParamsChange` дає застосунок, як у
   `useListState`.
3. **Склад `ListReport` (згори вниз):**
   - шапка (лише з `title`): h1 (`headingRef` — ціль фокуса після переходу), пояснення
     (`description`) і дії (`actions`); на вузькому контейнері дії під заголовком (`@container`,
     як `RecordHeader`);
   - вкладки-статуси з лічильниками — лише якщо є `tabs`;
   - FilterBar: пошук (`searchPlaceholder`), «Фільтри» з чипами (якщо є `filters`), меню видів,
     далі `toolbar`;
   - поки не застосовано вид за замовчуванням (`list.isReady`), на місці таблиці — скелетон: дані
     не вантажаться двічі;
   - таблиця `DataTable`: `mode: "scroll"` — великий список вікнами по 100 (`useWindowedList`),
     `mode: "pages"` — малий список сторінками по `perPage` (20) через `getList` ra-core, з
     попередньою сторінкою на екрані, поки летить нова, і першою сторінкою після нового фільтра,
     сортування чи компанії (і після повернення до попереднього фільтра — теж з першої); «Скинути
     фільтри» в стані «нічого не знайдено» — «Стандартний» вид;
   - ключ рядка — `getRowId`, за замовчуванням `id` запису; `columns`, `tabs`, `filters` і `defaults`
     стабільні між рендерами (`useMemo` чи константа).
4. **Елементи з ключами й порядком (ADR-0020):**
   - колонки — `DataTableColumn` (`id`), фільтри — `FilterDefinition` (`id`), вкладки — `ListTab`
     (`id`);
   - дії шапки й панелі фільтрів — `ListReportAction { id, node }`; масові дії —
     `ListReportBulkAction { id, render(count) }` у `bulk.actions`; кожна масова дія — окремий
     компонент у панелі вибраного, тож дія з хуками (`render: (count) => <Export count={count} />`)
     не ламає порядок хуків, коли панель з'являється й зникає;
   - порядок на екрані — порядок у списку; помічники злиття (додати, сховати, переставити за ключем)
     — крок 1.2 у `lib`, шаблон їх не потребує: він отримує вже злитий список.
5. **Вибір рядків лише з масовими діями:** `bulk = { actions, rowLabel, selectionLabel? }`; без
   `bulk` колонки прапорців і панелі вибраного немає. Тип не дає дій без `rowLabel`.
6. **Адреса — ввід ззовні:** без опису фільтрів у запит іде лише пошук `q` (хук завжди передає
   `filters` у `useListState`, хоч би й порожній список). Без фільтрів `FilterBar` не показує кнопки
   «Фільтри»: панель була б порожня.
7. **Демо:** «Дані й моки» — на шаблоні без зміни поведінки списку (вкладки, фільтри, види,
   «Прокрутка / Сторінки» в `toolbar`, погодження в `bulk`, редагування в комірці, права, конфлікт).
   Шапку (`ListReportHeader`) сторінка ставить над перевіркою сесії, як раніше `PageHeader`: якщо
   шапка з'являлась новим вузлом після перевірки, перший екран на CI зсувався на ~250 мс, а відгук
   на клік по прапорцю виходив за межу 200 мс (два прогони `pnpm perf`). Помітні відмінності: у шапці
   — дія «Створити рахунок» (як у стані «порожньо вперше»); після повернення до попереднього фільтра
   «Сторінки» починаються з першої. Фокус на h1 після переходу перевіряє e2e. Колонки рахунків —
   `invoice-columns.tsx`, номер і «Редагувати» — `invoice-row.tsx`.

## Наслідки

- Список у модулі чи проекті: `useListReport` + `ListReport` з колонками, фільтрами, вкладками й діями
  списками; своїх розкладок списку, джерел рядків і стану фільтрів не пишемо.
- Модуль B1 (крок 1.4) збирає контакти й компанії на шаблоні; розширення змінює списки елементів до
  того, як вони потраплять у шаблон.
- Бюджет JS маршруту «Дані й моки» — у межах (419,9 КБ gzip при межі 434,6): шаблон лише переніс
  код зі сторінки.
- Обмеження: збережені види увімкнені завжди (опції вимкнути немає, доки не знадобиться списку без
  видів); номер сторінки в `pages` не пишеться в адресу (після оновлення сторінки — перша), а
  `perPage` не запам'ятовується між візитами (вимога project-a — з B1); `q` з адреси чи виду працює й
  у списку без поля пошуку (видно лише «Скинути фільтри»); вкладки без `tabsLabel` підписуються
  назвою списку (без неї — назвою таблиці); дія шапки не має власного права — модуль загортає свою
  дію в `PermissionGate`, а розширення ховає дію модуля за ключем (`hide`, крок 1.2, ADR-0020).
- Крок 1.2: хук фокуса на h1 після переходу (`useFocusHeadingOnNavigation`) — у реєстрі
  (`hooks/use-focus-heading`), для обох шаблонів; адресу дає роутер застосунку.

## Розглянуті варіанти

- **Шаблон-розкладка лише зі слотами** (як Object Page): сторінка й далі сама складала б стан,
  види, лічильники й джерела рядків — саме те, що треба прибрати з модулів.
- **Шаблон, що сам тримає стан і віддає його через контекст чи render-prop:** масові дії й діалоги
  сторінки опинились би всередині шаблону або читали б контекст; хук поруч із компонентом простіший і
  типізований.
- **Дії й колонки як дочірні елементи JSX** (`<ListReport.Action id=…>`): розширення не змогло б
  змінити їх як дані до рендеру; масиви з ключами зливаються звичайною функцією.
