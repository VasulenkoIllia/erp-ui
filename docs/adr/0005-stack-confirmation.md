# 0005. Стек після стрес-сторінки: що підтверджено й що змінено

- Статус: прийнято
- Дата: 15.10.2026
- Хто ухвалив: за підсумками хвилі 0 (крок 0.6d); зміни, що вже ухвалив власник, — у
  згаданих ADR. Оцінка й докази — `docs/audit/2026-10-15-wave-0-final-report.md`.

## Контекст

SPEC §18.1: стрес-сторінка (список рахунків на 10 000 рядків із фільтрами, збереженим видом,
масовим погодженням і редагуванням у комірці, плюс картка запису) — пілот на Base UI + ra-core,
який «остаточно підтверджує стек». Хвиля 0 зібрала її в кроках 0.6a–0.6d («Дані й моки» в демо) і
перевірила на 360/768/1440 px, uk/en, світлій і темній темах, у Сапфірі й Графіті, обох
щільностях, з клавіатури, axe і в сценаріях моків. Швидкість — `pnpm perf` у CI (ADR-0009).

## Рішення

Стек SPEC §4 **підтверджено** з такими уточненнями.

1. **Підтверджено без змін:**
   - React 19, Vite, TypeScript strict, Tailwind CSS v4 з `@container` — уся адаптивність
     таблиці, карток, фільтрів і картки на контейнерних запитах;
   - shadcn/ui (CLI v4) на Base UI, стиль Nova (ADR-0001), зовнішні компоненти — лише перебудовою
     (ADR-0006); axe (WCAG 2.2 AA, зокрема розмір цілі) без порушень у 700+ e2e, forced-colors —
     одним правилом у `tokens/base.css`;
   - ra-core 5 як шар даних і прав: `dataProvider`/`authProvider` під наш контракт (ADR-0002,
     ADR-0003), `useGetList`/`useGetOne`/`useUpdate`/`useCanAccess`; список заповнює кеш
     картки (`useGetList` сам, вікна `useWindowedList` — так само) — шапка картки з'являється без
     запиту;
   - TanStack Query 5, TanStack Table 9 + TanStack Virtual — 10 000 рядків вікнами з сервера;
     react-hook-form + zod 4 (ADR-0015); i18next + Intl (ADR-0007); MSW зі сценаріями; Vitest,
     Playwright, axe-core; sonner; lucide-react; Geist.
2. **Змінено (вже ухвалено в інших ADR):**
   - **ReUI Data Grid → власна `erp/data-table`** на TanStack Table 9 + Virtual (ADR-0016): ReUI
     лишається довідкою; потрібні були розріджені вікна з сервера, грід і картки за W3C APG,
     колонки за шириною контейнера;
   - **cmdk і vaul не потрібні:** палітра — Base UI Autocomplete, шторки — Drawer/Sheet з Base UI
     (ADR-0008);
   - **qrcode.react, react-phone-number-input** не пройшли бар'єри — lean-qr і
     google-libphonenumber (ADR-0007, ADR-0011).
3. **Уточнено цим ADR:**
   - **Shadcn Admin Kit — не залежність.** Хвилі 0 вистачило хуків ra-core і власних компонентів;
     Admin Kit лишається джерелом коду для перебудови (ADR-0006), коли модулю знадобиться готовий
     CRUD-екран. Рядок SPEC §4 «CRUD: ra-core 5 + Shadcn Admin Kit» читається саме так;
   - **ra-core — лише хуки й провайдери**, без його компонентів і оптимістичного режиму
     `useUpdate`: вікна списку — власний `hooks/use-windowed-list` на `useDataProvider` і ключах
     ra-core; оптимістичне редагування — `useOptimistic` у комірці (ADR-0018); компанія — у `meta`
     ключа кешу (`companyScope`);
   - **AG Grid Community не перевірено:** стрес-сторінці вистачило `erp/data-table`. Рішення —
     коли з'явиться перший важкий екран (групування, зведення, тисячі колонок), окремим ADR після
     бар'єрів §18.2;
   - **бюджет JS:** ціль 250 КБ gzip на цьому стеку недосяжна (вхід демо — 342 КБ, самі бібліотеки
     ≈ 230–260 КБ); лишається храповик «факт + 5 %» на кожен маршрут (ADR-0009). Відгук і перший
     екран — у межах: INP 72 мс і LCP 1,25 с на телефоні (CPU ×4, 4G), INP 96 мс на десктопі з
     прапорцями й редагуванням у комірці при бюджеті 200 мс.

## Наслідки

- Хвиля 1 стартує на цьому стеку без заміни бібліотек; нові залежності — лише через бар'єри §18.2.
- Ризики, які лишаються відкритими: ручного проходу зі скрінрідером (NVDA, VoiceOver) не було —
  лише axe і перевірка ролей у e2e; AG Grid і FCL не перевірені; ліцензія й вибір xlsx — §20.
- Слабкі місця, які варто тримати під наглядом: `GridRow` без `memo` і `useUpdate` на кожну комірку
  (найповільніша дія на десктопі — клік по прапорцю, 88–120 мс у двох прогонах), бюджет маршрутів зростає на
  ≈ 1–5 КБ за крок.

## Розглянуті варіанти

- **Побудувати стрес-сторінку вдруге на альтернативі** (React Aria, власний шар на TanStack
  Router), як радило дослідження: подвоює хвилю 0, а жоден критерій не впав через стек — провали
  оцінки (FCL, шаблони, гарячі клавіші, офлайн) — це обсяг робіт, а не обмеження бібліотек.
- **Перейти на AG Grid Community для стрес-сторінки:** сторонні стилі й власна модель фокуса;
  власна таблиця вже проходить APG, axe і бюджет INP.
- **Відмовитись від ra-core на користь власного шару на TanStack Query:** ra-core дає права,
  вхід, кеш записів і мутації з ключами, які вже використовують лічильники й вікна; власний шар —
  більше коду без виграшу, поки контракт ADR-0002 тримається.
