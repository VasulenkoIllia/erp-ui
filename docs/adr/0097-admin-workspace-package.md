# 0097. Адмінка в монорепо: окремий пакет робочого простору

- Статус: прийнято (доповнює ADR-0029 і ADR-0096 п. 2; SPEC §3.3 без змін)
- Дата: 15.11.2026
- Хто ухвалив: власник, 15.11.2026 (обсяг кроку `Б10`: адмінка окремим пакетом робочого простору, CLI shadcn лишається
  в проекті); розміщення залежностей, чисте дерево й CLI в пакеті адмінки — уточнення в кроці за поведінкою команди кіта

## Контекст

- Сервер і адмінка часто живуть в одному репозиторії. Цілі файлів кіта — від теки з `components.json`: код у `src/`
  (`~/src/…` і псевдоніми `@/components`, `@/lib`, `@/hooks`), команда в `scripts/`, скіл у `.claude/skills/`, довідка в
  `docs/erp-ui/`, помічники e2e в `e2e/`, фоновий файл push у `public/`. Проект, де `src/` уже зайнято сервером, не мав
  куди поставити кіт, а як запускати кіт у монорепо, ніде не сказано й не перевірено.
- Команда кіта вже шукає lock-файл угору до кореня git (воркспейс) і ставить залежності менеджером пакетів у теці
  запуску. Чи це працює в підпакеті, чи не зачіпає корінь і сервер, CI не перевіряв.
- `shadcn init` записує `shadcn` у `dependencies` з `^` (найновіша версія), а посібник лише просив прибрати `^`. Пакет
  потрібен на машині розробника й у збірці (CLI і `shadcn/tailwind.css`, який імпортує `src/index.css` кіта), але
  `pnpm audit` проекту показує вразливості залежностей CLI серед залежностей застосунку.

## Рішення

1. **Адмінка — окремий пакет робочого простору.** Пакет (`apps/admin`) має свої `package.json`, `components.json`,
   `tsconfig` і `src/`, як звичайний проект Vite. Перше встановлення, `scripts/erp-ui-kit.mjs update` і `check`,
   `scripts/erp-ui-check-tokens.mjs` запускаються з теки пакета. Усі файли кіта лягають у пакет за тими самими цілями,
   що й в окремому проекті; корінь і сервер кіт не чіпає, крім lock-файлу воркспейсу. Цілей кіта не перенаправляємо:
   `src/` — тека пакета адмінки.
2. **Залежності — у `package.json` адмінки.** Рахуються лише записи цього пакета (ADR-0029, наявні записи як є):
   залежність, що є лише в корені чи в сервері, команда ставить адмінці з діапазоном кіта. Записів кореня й сервера
   команда не змінює.
3. **Чистим має бути весь репозиторій.** `update` пакета адмінки змінює й lock-файл у корені, тож зміни сервера, не
   закомічені, теж зупиняють оновлення: diff оновлення лишається окремим (ADR-0029). Повернути все —
   `git restore .` з кореня репозиторію.
4. **CLI shadcn — у `devDependencies` пакета адмінки, точна версія.** Одразу після `init` проект переносить `shadcn` з
   `dependencies` у `devDependencies` без `^`, на версію, з якою перевірено тег кіта. Команда бере CLI з
   `node_modules/.bin` теки запуску. SPEC §3.3 (закріплена в проекті CLI) не змінюється. Висновок про вразливості й що
   робити — посібник, розділ 8.
5. **Файли для Claude Code — у пакеті.** `CLAUDE.md` кореня імпортує `@apps/admin/docs/erp-ui/CLAUDE.project.md`;
   скіл `apps/admin/.claude/skills/erp-ui/` Claude Code вантажить, щойно працює з файлом пакета, а запущений з теки
   пакета — одразу.
6. **Перевірка в CI — задача «адмінка в монорепо»** (`pnpm workspace-smoke`) у PR, що змінює доставлене, поруч із
   «доставкою» й «оновленням»: робочий простір pnpm із сервером і адмінкою, кіт попереднього тегу командою тегу в пакеті
   адмінки, оновлення до коміту PR командою цієї версії. Задача перевіряє, що файли й `kit-files.json` лише в пакеті,
   нові залежності в його `package.json`, запис адмінки з точною версією не змінено, `package.json` кореня й сервера як
   були, lock-файл один, у корені; незакомічена правка сервера зупиняє `update`; typecheck і збірка адмінки, `check`,
   `check-tokens`; typecheck сервера зі схемами кіта з теки адмінки (ADR-0093). Без зеленої задачі PR не мерджиться.

## Наслідки

- Монорепо отримує кіт без нових правил у команді: та сама команда, ті самі цілі, лише тека запуску інша. Повідомлення
  команди називають теку пакета адмінки, а підказка «повернути все» — корінь репозиторію.
- Перевірено лише pnpm. npm, yarn і bun у теці пакета теж додають залежність у цей пакет, але CI цього не перевіряє.
- Спільний пакет стилів поза адмінкою (`../../packages/ui/…`) лишається поза підтримкою: `check-tokens` на ньому падає
  з кодом 1 (ADR-0096 п. 2), теки коду — аргументами.
- Сервер на TypeScript бере чистий шар контрактів із теки адмінки за шляхами `tsconfig` (ADR-0093 п. 5); окремого
  елемента реєстру для серверного пакета так само немає.

## Розглянуті варіанти

- **Цілі кіта з `components.json` (теку `src/` замінити текою стилів):** працює без окремого пакета, але тека стилів не
  завжди корінь коду (`app/` у Next.js — це маршрути), а команді й посібнику потрібне нове правило для кожного місця.
  Пакет адмінки дає те саме без змін у цілях. Відхилено.
- **Чисте дерево лише в пакеті адмінки:** менше комітів сервера перед оновленням, але lock-файл у корені змінюється разом
  з оновленням, і `git restore .` з теки пакета його не повертає. Відхилено.
- **CLI shadcn у корені воркспейсу:** pnpm не кладе CLI кореня в `node_modules/.bin` пакета, тож команді довелося б
  шукати його вище. CLI потрібен лише адмінці. Відхилено.
